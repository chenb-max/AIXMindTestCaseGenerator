# 跨页面流程构建规则

## 目标

基于多个页面解析结果，推断页面之间的跳转关系，形成可用于测试用例生成的流程模型。

## 核心原则

- 优先使用用户明确提供的流程描述。
- 其次使用页面顺序、页面角色、按钮文案和页面标题推断。
- 不创建用户没有提供或没有描述的中间页面。
- 对不确定跳转记录假设和置信度。

## 推断方法

### 页面角色顺序

常见顺序：

```text
start -> middle -> middle -> result
```

示例：

- 列表页 -> 编辑页 -> 详情页。
- 上传页 -> 确认页 -> 结果页。
- 订单页 -> 地址页 -> 支付页 -> 支付结果页。

### 按钮文案

| 源按钮 | 目标倾向 |
| --- | --- |
| 下一步、继续 | 下一个中间页 |
| 确认、提交 | 结果页或下一个中间页 |
| 返回、取消、上一步 | 上一页或入口页 |
| 查看详情 | 详情页 |
| 编辑、修改 | 编辑页 |

### 流程描述

如果用户提供了如“列表页点击新增 -> 编辑页填写 -> 详情页查看结果”的描述，应优先按描述中的顺序和动作建立跳转。

## 输出模型

```json
{
  "flow_name": "文件上传流程",
  "entry_page": "文件列表页",
  "exit_pages": ["上传结果页"],
  "pages": [
    {"page_id": "page-1", "page_name": "文件列表页", "page_role": "start"},
    {"page_id": "page-2", "page_name": "文件上传页", "page_role": "middle"}
  ],
  "transitions": [
    {
      "from": "page-1",
      "to": "page-2",
      "trigger": "点击上传按钮",
      "type": "main"
    }
  ],
  "main_path": ["page-1", "page-2"],
  "alternate_paths": []
}
```

## 边界处理

- 页面顺序不明确：按角色和按钮文案重新排序，并记录推断依据。
- 跳转目标不明确：在模型中标注 `unknown`，后续用例中不要伪造目标页。
- 存在循环：允许返回或重新编辑的循环路径，但要区分主流程和分支流程。
- 缺少结果页：不要虚构结果页，可将提交后的系统响应作为待验证结果。

## 流程摘要到测试意图

流程模型只描述页面、动作、状态和数据传递；先完成流程摘要，再设计测试意图。至少检查：

- 主路径是否由用户描述或页面证据支持。
- 返回、取消、中断和重新编辑是否有依据。
- 页面之间展示的数据是否需要保持一致。
- 未知目标、循环或缺失结果页是否已记录为假设或 warning。

不要为了满足覆盖分类而添加不存在的中间页面。没有依据的异常跳转、状态一致性和重复提交场景应在测试意图中标记为 `inferred`。
