# 图片分析指南

## 目标

从 UI 截图中识别页面结构、交互元素和流程线索，避免生成无依据的测试用例。

## 识别优先级

1. 用户标注区域，如红框、箭头、文字说明。
2. 页面标题、面包屑、步骤条。
3. 表单字段、按钮、链接、Tab。
4. 提示信息、状态标签、空数据说明。
5. 表格列、卡片字段、结果摘要。

## 页面类型

- 列表页：包含数据列表、筛选条件、新增或查看入口。
- 表单页：包含输入控件、保存、提交、下一步。
- 确认页：展示前一步输入信息，包含确认、返回。
- 结果页：展示成功、失败、完成或结果详情。
- 弹窗或抽屉：默认视为当前页面的一部分，除非用户明确要求作为独立流程。

## 控件识别

记录以下内容：

- 文本框、数字框、日期选择、上传控件。
- 下拉框、单选、多选、开关。
- 主按钮、次按钮、危险按钮。
- 表格、分页、排序、筛选。
- 错误、警告、成功、加载中、禁用状态。

## 多图联合分析

多张截图时：

1. 先按 `page_order` 排序。
2. 没有顺序时，按页面角色和按钮文案推断。
3. 对相同页面的不同状态，记录差异而不是当作新页面。
4. 对页面之间的数据字段做映射，例如上传页文件名到确认页文件名。

## 不确定项

- 文字模糊：标注为文字不清晰，不生成精确字段用例。
- 按钮含义不明：根据文案给出低置信度推断，并记录假设。
- 页面关系不明：不要虚构中间页，可在警告里提示需要补充。

## 事实边界

- 只有清晰可读且能定位到截图区域的内容才可作为 `visible` 事实。
- 不要根据图标外观猜测危险操作、权限或后端行为。
- 不要把截图外的默认值、校验规则、下拉选项或错误码补写成事实。
- 同一页面的不同截图优先整理为状态差异，不要自动创建多个页面。
- 识别失败时保留“不确定”标记；后续可以生成确认型风险意图，但必须使用 `source: inferred`、具体假设和较低置信度。

}
