# 页面解析规则

## 目标

从单张 UI 截图中提取结构化页面信息，为流程构建和用例生成提供基础数据。

## 页面信息

优先按以下来源识别页面名称：

1. 页面标题。
2. 顶部主标题。
3. 面包屑最后一级。
4. 可见 URL 或路由。
5. 页面主要功能区域标题。

页面角色：

- `start`：列表、概览、入口页，通常包含新增、上传、创建、开始等入口按钮。
- `middle`：表单、确认、编辑、支付等中间步骤页。
- `result`：成功、失败、完成、结果摘要页。
- `single`：没有明显跨页面流程的单页功能。

## UI 元素

识别并记录：

- 输入控件：字段名、类型、占位符、必填标识、可见校验提示。
- 按钮：文案、主次关系、可能触发的行为。
- 展示区域：表格列、卡片字段、结果摘要、提示信息。
- 导航元素：返回、面包屑、步骤条、Tab、链接。
- 状态元素：成功、失败、禁用、加载中、空数据。

## 行为提取

常见按钮语义：

| 文案 | 行为倾向 |
| --- | --- |
| 新增、创建、上传 | 从入口页进入编辑或上传页 |
| 下一步、继续 | 进入下一个流程步骤 |
| 确认、提交、保存 | 提交当前页面数据 |
| 返回、取消、上一步 | 回到上一页或入口页 |
| 查看详情 | 进入详情页 |
| 编辑、修改 | 进入编辑页 |

## 约束

- 不假设截图外的隐藏控件。
- 不假设未展开下拉框的全部选项。
- 不假设未展示的校验规则。
- 模糊文本标注为文字不清晰。
- 多种可能的页面角色需要记录推断依据。

## 事实摘要

页面解析阶段只记录页面事实，不直接生成完整测试用例。内部摘要至少区分：

- 清晰可见的页面、控件、状态和提示。
- 用户或需求明确描述但截图未展示的行为。
- 根据按钮语义或页面顺序推断的关系。
- 仍然未知或存在冲突的内容。

`visible` 只能用于截图中清晰可见的事实；按钮目标、隐藏校验规则和未展示选项不得标记为 `visible`。不确定内容应降低置信度并交给流程摘要或测试意图阶段处理。
